# AIGC 降重工具

把论文段落交给大模型做"去 AI 化"改写，用于降低 AIGC 检测率。

线上：https://reduce-aigc.pages.dev/ 　（部署状态随时可用 `GET /api/health` 确认版本）

> ⚠️ 文本与你的 API Key 会经由本服务转发给第三方大模型 API。改写结果仅供写作参考，请遵守所在机构关于 AI 使用的规定，不要用本工具规避学术诚信要求。

## 架构

单一代理实现，三个入口共用：

| 文件 | 角色 |
|---|---|
| `index.html` | 全部前端（无框架、无构建）。策略、分段改写、历史、对比、自查 |
| `functions/_lib/rewrite-handler.mjs` | **唯一**的代理核心：模型路由、鉴权、超时、重试、流式、限流、CORS |
| `functions/api/rewrite.js` | Cloudflare Pages Functions 入口（`/api/rewrite`） |
| `functions/api/health.js` | 健康检查（`/api/health`） |
| `_routes.json` | Pages 侧路由面：只让 `/api/*` 触发 Functions，其余走静态资源 |
| `_redirects` | 挡住不该公开的开发文件（见「发布面」） |
| `worker.js` | Cloudflare Workers 入口 + 静态资源安全响应头 |
| `server.js` | 本地开发服务器，复用同一代理核心 |

> 改代理行为只需改 `functions/_lib/rewrite-handler.mjs`，三个入口都只是薄封装。
> Pages 侧的路由面由仓库根的 `_routes.json` 限定在 `/api/*`（官方机制），因此 `functions/_lib/`
> 只是被 import 的源码模块，不会成为可访问路由，同时也能省掉静态请求的 Functions 调用计费。

## 代理接口

只有一个接口，自己部署时可直接对接：

```http
POST /api/rewrite
Content-Type: application/json

{
  "apiKey": "sk-...",                        // 必填，用户的密钥
  "baseUrl": "https://api.deepseek.com/v1",  // 必填，上游地址（只填到 /v1 会自动补 /chat/completions）
  "model": "deepseek-chat",                  // 必填，原样透传给上游
  "authType": "bearer",                      // 可选，bearer（默认）| apikey
  "messages": [{ "role": "user", "content": "..." }],
  "temperature": 0.8,
  "max_tokens": 4096,
  "stream": false,
  "extraBody": { "thinking": { "type": "disabled" } }   // 可选，透传上游专属参数
}
```

- 成功：直接把上游的 JSON 原样返回（代理不改写响应体）
- 失败：`{ "error": "..." }`，状态码沿用上游或用 400/403/413/429
- `GET /api/health` → `{ ok, service, version, models: "user-supplied" }`

代理侧的限制：请求体 ≤256KB、`messages` ≤40 条且合计 ≤12 万字、`extraBody` ≤2000 字符 / 20 个键、
`messages` 与 `stream` 不允许被 `extraBody` 覆盖；默认拒绝内网与本机地址（SSRF 防护）。

## 部署

### 方式一：Cloudflare Pages（当前线上用的就是这条）

1. 把仓库推到 GitHub（**注意**：git 若被 `url.*.insteadOf` 重写到镜像站，镜像站证书异常时会全部失败，见下方"已知环境问题"）
2. Cloudflare 控制台 → Workers & Pages → 选该项目 → 触发一次重新部署（Git 集成项目每次 push 会自动构建）
3. Build command 留空，Build output directory 填 `/`
4. 部署后打开 `/api/health`，确认版本号

> Git 集成型 Pages 项目**不能**再用 `wrangler pages deploy` 直传，二者互斥。

### 方式二：Cloudflare Workers（不依赖 GitHub）

```bash
npx wrangler login     # 需要你本人授权
npx wrangler deploy
```

配置见 `wrangler.jsonc`（`main` = `worker.js`，`assets.directory` = 仓库根目录）。
`.assetsignore` 决定哪些文件不会被当作静态资源上传（`.git`、`functions/`、`scripts/`、`server.js` 等已排除）。
本地可先验证打包而不发布：

```bash
npx wrangler deploy --dry-run
```

### 可选环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `ALLOWED_ORIGINS` | 空 | 逗号分隔的跨域白名单。留空时只放行同源与本地环回请求 |
| `RATE_LIMIT_PER_MIN` | 30 | 单 IP 每分钟请求上限（按 isolate 内存计数，尽力而为） |
| `UPSTREAM_TIMEOUT_MS` | 25000 | 上游请求超时 |
| `ALLOW_PRIVATE_UPSTREAM` | 空 | 设为 `1` 才允许把请求发到内网/本机地址（连自建模型时用） |

## 发布面（重要）

- **Pages 路径**：发布面 = 仓库里**所有被跟踪的文件**（Build output directory 是仓库根）。
  `.assetsignore` 在 Pages 上**不生效**，它只对 Workers 静态资源有效。
  因此 `server.js`、`scripts/`、`worker.js` 等开发文件默认会一起被发布 —— 用 `_redirects` 挡（见下）。
- **Workers 路径**：发布面 = `assets.directory` 减去 `.assetsignore` 里列出的文件。

`_redirects` 只支持 301/302/303/307/308（**不支持 404**），所以用 302 把开发文件指回首页，
内容不再可取。**规则由 `scripts/gen-redirects.mjs` 从 `git ls-files` 生成**（`npm run gen:redirects`），
所以新增根目录文件后跑一次就不会漏；e2e 会断言清单与文件一致。改完务必跑 `npm run probe:live`。

**为什么没改成 `public/` 发布目录**：那样需要重建 Pages 项目的目录结构并在控制台改
Build output directory，切换过程中容易把线上弄挂（构建用的目录一旦不存在就会部署失败）。
当前「生成式黑名单 + 测试守护 + 线上探测」已经把风险堵住，收益不足以换这个风险。
若你仍想彻底收窄，步骤是：建 `public/` 只放 `index.html` 与 `announcement.json` → 控制台把
Build output directory 改成 `public` → 删掉 `_redirects` 与根目录副本（顺序别颠倒）。

## 使用

1. 打开页面 → ⚙ → **先添加模型**（见下一节）→ 再添加该服务的 API Key（只存在你自己的浏览器里）
2. 粘贴段落，或拖入 `.docx` / `.txt` / `.md`（**可一次拖入多个，按文件名顺序合并**）
3. 选策略（结构 / 风格）与强度（普通 / 重度）→ 开始改写（`Ctrl / ⌘ + Enter` 也行）
4. 超过 2000 字会自动分段（每段约 500 字，段间带上文保持指代一致），全程可点「⏹ 停止」

改写完成后：

| 能做什么 | 说明 |
|---|---|
| ⚡ 流式输出 | 上游边生成边显示，长文本不用等整段写完（上游不支持流式时自动退回一次性请求） |
| ✂️ 局部改写 | 在左侧**选中一段**再点开始，就只改选中部分；结果旁的「↩ 替换到原文」可把它替换回去，其余原文不动。对比视图里点「↖ 改这句」可直接在原文中选中该句 |
| 🔍 质量自检 | 自动比对**技术信息是否丢失**与**改写幅度**。结论并入右栏底部那行元信息（相似度、丢失数量）；**提示块每次会话只出现一次**（仅首次改写时），之后不再打扰。后续若丢了技术信息，元信息行会带 `⚠ 丢失 N 处技术信息` |
| 📄 导出 Word | 生成 `.doc`，段落带首行缩进，Word / WPS 直接打开 |
| 💾 下载 MD | 带上策略、强度、模型、时间与原文对照 |
| ✨ 再降一次 | 把结果放回左侧当新原文迭代处理，比一次硬改更稳 |
| 📊 对比视图 | 中文按字级 diff，能看清具体改了哪些字 |
| 📜 改写历史 | 保存全文（最多 50 条），支持**搜索**、载入原文重改、单条复制、**全部导出为 Markdown** |

设置里还有三样：**补充说明**（给模型一句额外要求，如"保留所有专业术语"，会追加到每次请求的指令里）、
**配置导入导出**（换设备时把模型列表与偏好一次性带走；出于安全**不含 API Key**）、
**用量**（累计改写次数、处理与产出字数，以及上游返回的 token 数；只记客观数据、不做价格推测，可一键清零）。

其他：输入内容每 600ms 自动存本地草稿，误刷新可恢复（设置里可关）；改写过程中关页面会弹确认；
Esc 可关闭任意弹窗；`Ctrl/⌘+Enter` 开始改写；深浅色跟随系统。

## 模型：全部由你自己配置

**本工具不内置任何模型。** 打开 ⚙，在「添加 / 管理模型」里填四项即可：

| 字段 | 说明 |
|---|---|
| 名称 | 随便起，仅用于下拉里区分 |
| API 完整地址 | 必须为 https（内网地址需服务端开 `ALLOW_PRIVATE_UPSTREAM`）；只填到 `/v1` 会自动补 `/chat/completions` |
| 模型 ID | 该服务要求的模型名，原样透传 |
| 鉴权方式 | `Bearer`（多数服务）或 `api-key` 头（小米 MiMo、Azure OpenAI 这类） |

再在同一个面板里加 API Key（两个下拉/输入互不干扰），点「🔌 测试当前模型」就能当场验证
鉴权与参数是否被接受 —— 它会用你的 Key 真打一次上游（`max_tokens: 32`，只花几十 token），
成功显示返回内容与耗时，失败直接显示上游原始报错。

这是唯一需要配的东西；没有配置时「开始改写」会拦住并提示先添加模型。

### 已知上游的参数适配（自动生效）

填了**官方域名**时会自动套用官方文档里查到的硬约束（依据 2026-09 核对）。这不是模型清单，
填别的域名就不套用：

| 域名 | 自动处理 | 原因 |
|---|---|---|
| `*.bigmodel.cn` | 温度上限 1.0、`max_tokens` 上限 8192、关闭思考模式 | 官方最大输出很大，默认开思考会挤占正文 |
| `*.xiaomimimo.com` | 温度上限 1.5、关闭思考模式 | 温度范围只有 0–1.5；默认开思考会挤占正文 |
| `*.dashscope.aliyuncs.com` | `max_tokens` 上限 4096 | 输出上限较小 |

> 「关闭思考模式」= 请求里带 `thinking: { type: "disabled" }`。改写是风格转换而非推理，
> 开着思考会把 `max_tokens` 吃光导致正文为空。若某模型不接受该参数，删掉
> `functions/_lib/rewrite-handler.mjs` 里 `UPSTREAM_PROFILES` 对应那行 `extraBody` 即可。

### 「上游只返回了思考内容」怎么办

推理型 / 思考型模型（名字里带 `reason`、`think`、`R1` 这类）在回答前会先输出一大段思考，
**思考 token 也计入 `max_tokens`**。预算被思考吃满时，正文就是空的（上游返回 `finish_reason: length`）。

工具现在会自己处理三层，逐级降级：

1. **自动放大预算重试**：检测到"只有思考内容、没有正文"时，把 `max_tokens` 逐级翻倍（最多 4×，
   上限 16384）重试，多数情况这一步就好了
2. **勾「关闭思考模式」**：在模型设置里勾上，请求会带 `thinking: { type: "disabled" }`。
   若上游不认这个参数，工具会**自动去掉它再试一次**，不会让你卡在参数错误上
3. **换非推理型号**：若上游根本没提供关闭开关，就得换型号（通常不带 `reason` / `think`）

另外：填的是**官方域名**时（`*.bigmodel.cn`、`*.xiaomimimo.com`）工具会自动关思考；
填第三方中转地址时这个自动处理不生效，需要手动勾。

「🔌 测试当前模型」也会告诉你实情：连通但只回了思考内容时，会直接说明思考占了多少字、
完成原因是什么，而不是含糊地报失败。

### 内网 / 本机模型

默认**禁止**把请求发到内网与本机地址（SSRF 防护）。要连本机自建模型（Ollama、vLLM 等），
让服务端设置 `ALLOW_PRIVATE_UPSTREAM=1`，本地开发时就是 `ALLOW_PRIVATE_UPSTREAM=1 npm start`。

## 安全与隐私

- API Key 仅存放在浏览器（默认 localStorage；可在设置里改成仅本次会话，关闭浏览器即清除）
- 但每次请求都会把你的 Key 与文本经本代理转发给上游 —— **不要使用你不信任的第三方部署**
- 跨站请求默认拒绝；若自建且需要被其它域调用，用 `ALLOWED_ORIGINS` 显式放行
- "AI 痕迹自查"是让模型给自己打分，**不是**权威查重/AIGC 检测，分数会偏乐观

## 已知环境问题（本机）

- 全局 git 配置存在 `url.https://kkgithub.com/.insteadof = https://github.com/`，
  该镜像站当前 TLS 证书校验失败（`SEC_E_WRONG_PRINCIPAL`），**所有走 github.com 的 git 操作都会失败**。
  实测直连 `github.com` 正常，临时绕过（不改全局配置）：

  ```bash
  GIT_CONFIG_GLOBAL=/dev/null git push https://github.com/<用户>/<仓库>.git main
  ```

- 本机 `gh` 已安装但**未登录**，HTTPS 与 SSH（`~/.ssh/id_ed25519` 未注册）都无可用凭据，
  推送前需先 `gh auth login` 或配置 PAT。
- `raw.githubusercontent.com` 在本机不可达，故公告改为**同源优先**（`/announcement.json`）。

## 界面

- **左右两栏共用五层骨架**：`标题+字数` → `工具行(36px)` → `内容区(flex:1，两栏等高)` → `底部行(说明 + 操作)`，
  逐层 y 坐标对齐（用断言守住：卡片 / 内容区 / 工具行 / 底部按钮行的偏差都必须 ≤1px）
- **视觉语言**：一套设计令牌（圆角 4 级、阴影 3 级、字号收敛），主区 1200px 定宽、卡片 22px 内边距，
  策略/强度/结果视图统一为轻量分段控件；面板标题去掉装饰性 emoji，层级交给字号与字距
- **二级界面为液体玻璃**：设置弹窗、历史 / 检测 / 公告抽屉、轻提示统一使用
  `backdrop-filter: blur(30px) saturate(180%)` + 半透明底 + 1px 内高光 + 22px 圆角，
  遮罩层同时做 5px 虚化；侧边面板改为留边悬浮的玻璃板而非贴边抽屉
- **深浅双主题**：全部颜色走 CSS 变量，跟随系统 `prefers-color-scheme`；
  不支持 `backdrop-filter` 的浏览器自动退化为不透明面板
- 背景加了极淡的三点光晕（不透明度 0.09–0.15），让玻璃有可虚化的内容，同时保持整体干净
- 无障碍：`:focus-visible` 焦点环、`prefers-reduced-motion` 降级、滚动条与对比度统一处理

## 变更记录

### 3.10.0（安全：SSRF 防护加固）
- **发现并修掉 6 种绕过 SSRF 防护的写法**。原判定只认「点分十进制 4 段」，
  下列写法一律被放行，而它们在 `fetch` 里都会解析到 127.0.0.1：
  `2130706433`（十进制）、`0x7f000001`（十六进制）、`0177.0.0.1`（八进制）、
  `127.1`（短写）、`[::ffff:127.0.0.1]`（IPv4 映射 IPv6）、`LOCALHOST.`（尾点域名）
- 改法：**先规范化再判定，规范化不出来又长得像 IP 的按内网拒绝**（保守优先）。
  同时补齐 IPv6 内网段（`fc00::/7` 唯一本地、`fe80::/10` 链路本地），
  公网 IPv6 与 172.16/12 边界仍正常放行
- 25 个判定用例固化为 3 条断言（含等价写法、公网不误拦、保守策略），避免回归
- 测试 191 → 194 项

### 3.9.0（健壮性：畸形上游 + 多标签页）
- **流式中途断开不再被当成完整结果**：上游半路断连、没发 `[DONE]` 或 `finish_reason` 时，
  半截内容此前会被直接接受。现在识别结束标记，缺失时提示「结果可能不完整，请核对末尾」
  （不直接报错 —— 有些上游本来就不发结束标记，硬失败会误伤）
- **HTML 错误响应被清洗**：上游报错常返回整页 HTML，此前原样塞进错误信息（满屏标签）。
  现在剥标签、解实体、压一行：`<h1>502 Bad Gateway</h1>` → `502 Bad Gateway`
- **上游结构不符时给精准诊断**：有响应但缺 `choices`（多半是 API 地址填错、打到了别的接口），
  此前只说「返回为空」；现在直接提示检查地址是否指向 chat/completions
- **多标签页同步**：两个标签页同开时，另一页改了 Key / 模型 / 历史 / 用量，本页此前毫无感知
  （继续操作还会用旧快照覆盖别人）。现在监听 `storage` 事件刷新对应界面；无关的键不触发渲染；
  输入草稿只在本地为空时跟随，避免抢光标
